# MuscleMetrics Roadmap

> A sequencing document, not a promise of release dates.

## Status language
- **LIVE** — implemented in the current product.
- **NOW** — active foundation/near-term work.
- **NEXT** — follows current foundations.
- **LATER** — approved direction but not near-term implementation.
- **EXPLORE** — research only.

## LIVE
- Workout/plans creation and editing.
- Live workout logging and recovery/persistence.
- Workout history.
- Goals and achievements.
- Progress and deep analytics.
- Steps/consistency tracking.
- Progressive onboarding.
- Social feed, sharing, profiles and notifications.
- Light/dark design system.
- Core app direction moved away from paid-tier gating.

## NOW
1. Keep core functionality free and ensure legacy paywall code is not called by product pages.
2. Add a user feedback/suggestions path.
3. Maintain stability and polish across current flows.
4. Establish this documentation as the development source of truth.
5. Build/redesign the official MuscleMetrics product website while preserving legal routes.

## NEXT — adaptive training foundations
Implement in order:
1. readiness storage;
2. systemic fatigue;
3. muscle fatigue;
4. today's e1RM prediction;
5. working-weight recommendation;
6. prediction vs actual storage;
7. accuracy;
8. user-specific coefficient learning.

## LATER — Coach / PT
- Coach mode.
- Client invitation/onboarding questionnaire.
- Client management.
- Individual programming and notes.
- Availability/booking.
- Session bundles.
- Payment/commission flow.
- Coach analytics.

## EXPLORE
- Apple Health-assisted readiness/sleep inputs.
- Apple Watch/expanded wearable experience.
- More adaptive training intelligence.
- Video/form analysis where technically and scientifically justified.

## Roadmap discipline
A new idea should not automatically become NOW. Record it in the relevant specification, decide whether it supports the current product objective, then place it in sequence.

Update this document when a feature meaningfully changes status.
